# التحديث الأخير — دخول مباشر وتجربة قابلة للحفظ

افتح START-HERE.html بعد فك الضغط: سينقلك مباشرة إلى تسجيل الدخول.

- المعاينة المستقلة تحتوي بيانات توضيحية فقط، ولا تستخدم قاعدة MongoDB.
- في التشغيل الحقيقي تختار رقم المدير وكلمة مروره أثناء تهيئة النظام؛ لا توجد كلمة مرور ثابتة داخل المشروع.
- يمكنك إنشاء مشاريع وموظفين وتقارير وعقود، وكتابة الملاحظات ورفع صور الكشوفات وصورة الملف والشهادات في التجربة المحلية.

- الحساب المحلي تجربة على جهازك، وليس حسابًا سحابيًا أو نظام صلاحيات آمنًا على جهاز مشترك. ملف preview-data.js خارج public ولا يُنشر على Cloudflare.

# Almasri Engineering — إدارة المشاريع والكشوفات والتقارير والعقود

مشروع كامل المصدر بثلاث لغات: Cloudflare Worker + واجهة HTML/CSS/JavaScript + MongoDB.
الشعارات والخلفيات المرفقة مدمجة في `public/assets`.

## ابدأ هنا

1. فك ضغط الملف كاملًا.
2. افتح `preview.html` بالنقر المزدوج لمعاينة التصميم بدون تثبيت. هذه تجربة محلية تحفظ التعديلات في نفس المتصفح فقط.
3. افتح مجلد `engineering-portal` في VS Code بواسطة File → Open Folder.
4. لتشغيل النظام الحقيقي اتبع الخطوات التالية. فتح `public/index.html` مباشرة أو استخدام Live Server وحده لا يشغّل الخادم أو قاعدة البيانات.

## ما يحتويه النظام

- مدير رئيسي وحسابات موظفين، وتعديل البيانات والصلاحيات وتعطيل الحساب وحذفه.
- رقم الموظف هو اسم الدخول؛ لا توجد كلمات مرور افتراضية.
- مشروع واحد مخصص لكل موظف في هذه النسخة، مع إدارة المشاريع وصورها ومواقعها.
- كشوفات مخصصة لموظف مع ملاحظات وصور وموقع وتاريخ ونتيجة.
- الموظف يقرأ مشروعه وكشوفاته فقط، وينشئ كشفًا ميدانيًا ضمن مشروعه بحالة انتظار المراجعة، ويضيف الموقع والملاحظات والصور لكشوفاته فقط.
- الموظف يعدّل اسمه ومهنته وهاتفه، ويرفع صورة ملف/خلفية وشهادات أو أوراقًا بصيغة PDF أو صورة؛ تظهر هذه الملفات للمدير داخل ملف الموظف.
- المدير ينشئ ويعدّل ويحذف الموظفين والمشاريع والكشوفات والملاحظات والصور.
- لوحة تحكم، بحث وتصفية وصفحات نتائج، وMy Inspections.
- يَظهر اسم الموظف ورقم دخوله في الكشف، واسم من أنشأ السجل أو أضاف الملاحظة أو الصورة.
- اختيار المشروع في النماذج قابل للتوسع، مع خيار إضافة مشروع جديد يدويًا وحفظه مباشرة.
- قسم «العقود» للمدير: تواريخ يدوية، طرفان، بنود العقد، شعار ثابت، مساحات توقيع وختم، وطباعة PDF.
- جلسات دخول في MongoDB مع Cookie من نوع HttpOnly، تنتهي بعد 12 ساعة.
- كلمات المرور مخزنة كاشتقاق PBKDF2-SHA256 مع ملح عشوائي و600,000 دورة؛ ليست نصًا صريحًا.
- صور الكشوفات JPG/PNG/WebP حتى 3 MiB للصورة، وملفات الموظف JPG/PNG/WebP/PDF حتى 8 MiB للملف، محفوظة Binary في مجموعة الصور داخل MongoDB. لا يُستخدم localStorage لحفظ أعمال المستخدم.

## إعداد MongoDB Atlas مرة واحدة

1. أنشئ Cluster من حسابك في MongoDB Atlas.
2. من Database Access أنشئ مستخدم قاعدة بيانات مخصصًا، مع صلاحية `readWrite` على قاعدة `engineering_portal` فقط. هذا المستخدم مختلف عن حساب مدير الموقع.
3. من Connect → Drivers انسخ رابط `mongodb+srv://...`، وضع اسم المستخدم وكلمة المرور الفعليين. إذا احتوت كلمة المرور رموزًا خاصة يجب ترميزها في الرابط وفق percent-encoding.
4. أضف عنوان IP التطوير إلى Network Access. وللنشر، يجب أن تسمح سياسة الشبكة باتصال Cloudflare بقاعدة البيانات. Workers لا يعطي المشروع عنوان خروج ثابتًا افتراضيًا؛ يُحدد إعداد شبكة الإنتاج قبل النشر. لا توسّع الوصول تلقائيًا ولا تعطل TLS أو التحقق من الشهادات.
5. لا ترسل كلمة المرور أو رابط الاتصال إلى موظفيك، ولا تضعهما داخل ملفات `public`.

## التشغيل في VS Code

ثبّت Node.js 22 LTS أو أحدث. افتح Terminal → New Terminal داخل مجلد المشروع:

```bash
npm ci
```

انسخ `.dev.vars.example` إلى `.dev.vars` داخل نفس المجلد. في Windows PowerShell:

```powershell
Copy-Item .dev.vars.example .dev.vars
```

ضع داخل `.dev.vars` رابطك الحقيقي ورمز تهيئة عشوائيًا. لتوليد الرمز:

```bash
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

ثم:

```bash
npm run dev
```

افتح `http://localhost:8787`. سيظهر إنشاء المدير لأول مرة: أدخل رمز التهيئة، اسم المدير، رقم الدخول، وكلمة مرور بطول 6 أحرف على الأقل. بعد الإنشاء سجّل الدخول. إنشاء الفهارس يتم في هذه الخطوة.

عند التجربة محليًا يحتاج الخادم إلى البقاء قيد التشغيل. بعد النشر لا يحتاج المستخدمون VS Code أو أوامر أو كمبيوترك.

## النشر لاحقًا على حساب Cloudflare الخاص بك

المشروع لم يُنشر ولم يُربط بأي حساب سحابي ضمن هذا التسليم. عندما تقرر النشر:

```bash
npx wrangler login
npm run build
npx wrangler secret put MONGODB_URI
npx wrangler secret put SETUP_TOKEN
npm run deploy
```

الأمران `secret put` يطلبان القيمة عبر إدخال مخفي؛ لا تكتب الأسرار داخل `wrangler.jsonc`.
إذا طُلِب إنشاء Worker أولًا عند حفظ الأسرار، أنشئه بالاسم `engineering-portal` أو نفّذ `npm run deploy` لإنشاء التطبيق غير المهيأ، ثم احفظ الأسرار وأعد النشر. الواجهة لا تعمل على بيانات وهمية عند غياب الإعدادات.

يمكن تغيير `name` في `wrangler.jsonc` قبل النشر. في حال استخدام قاعدة جديدة ستحتاج إنشاء المدير مجددًا. في حال استخدام نفس قاعدة التطوير تبقى البيانات والحسابات نفسها.

بعد إنشاء المدير احذف سر التهيئة من الإنتاج:

```bash
npx wrangler secret delete SETUP_TOKEN
```

سيبقى تسجيل الدخول وإدارة الموظفين يعملان. إنشاء مدير ثانٍ من صفحة التهيئة ممنوع بعد وجود المدير الرئيسي.

لا يلزم R2 أو D1؛ البيانات والصور في MongoDB كما طُلب. حجم الصور يستهلك مساحة Atlas. الاستضافة وقاعدة البيانات لهما حدود استخدام وخطط؛ ليست هناك ضمانة باستمرار الخدمة مجانًا أو حفظها إلى الأبد. فعّل نسخ Atlas الاحتياطية وفق خطتك. اشتقاق كلمات المرور قد يتجاوز حد CPU للخطة المجانية في Workers؛ اختبر خطة الحساب عند النشر واستخدم خطة مناسبة دون تقليل قوة حماية كلمات المرور.

## سياسة الصلاحيات والحذف

| الإجراء | المدير | الموظف |
|---|---|---|
| إدارة الموظفين وصلاحياتهم | نعم | لا |
| إنشاء/تعديل/حذف مشروع أو كشف | نعم | إنشاء كشف جديد ضمن مشروعه فقط |
| الاطلاع على المشاريع | جميع المشاريع | المشروع المخصص له |
| الاطلاع على الكشوفات | جميع الكشوفات | المخصصة له ضمن مشروعه الحالي |
| إضافة ملاحظة/صورة لكشف | نعم | لكشفه فقط |
| تعديل البيانات الشخصية وصورة الملف والشهادات | يرى ويدير | يعدّل ويرفع ملفاته فقط |
| تعديل/حذف الملاحظات والصور | نعم | لا |
| صور المشروع | إضافة وقراءة وحذف | قراءة ضمن مشروعه |

- تغيير صلاحية أو بيانات موظف ينهي جلساته الحالية؛ حذف الحساب أو تعطيله يمنع الدخول فورًا.
- نقل الموظف لمشروع آخر يخفي كشوفات المشروع السابق عنه. المدير يعيد تخصيصها عند الحاجة.
- حذف موظف أو مشروع أو كشف هو حذف مؤرشف: يُخفى من التطبيق، وتبقى السجلات في MongoDB للحفاظ على تاريخ العمل. لا توجد واجهة استعادة في هذه النسخة.
- حذف مشروع يخفي كشوفاته وصوره بما فيها روابط الصور المباشرة. حذف صورة مفردة أو ملاحظة يحذفها فعليًا.
- لا يمكن حذف المدير الرئيسي أو تعطيله أو تحويله لموظف.
- حد الملاحظات 200 لكل كشف، وطول الملاحظة 4,000 حرف؛ يمكن إنشاء كشف متابعة عند بلوغ الحد.

## التحقق وحدود الاختبار

```bash
npm test
npm run build
```

نتيجة الفحص الحالي: نجح فحص صياغة ملفات JavaScript، ونجح سيناريو المعاينة الذي يسجل دخول موظف، يعدّل ملفه، يرفع صورة وشهادة، ينشئ كشفًا بموقع وملاحظة، ثم يراه المدير. اختبار الاتصال الفعلي بـMongoDB يحتاج بيئة قاعدة بيانات.

اختبارات الوحدة والصلاحيات لا تحتاج قاعدة فعلية، وتستخدم بيانات اختبار معزولة. اختبار التكامل الحقيقي يُفعّل فقط عند ضبط `TEST_MONGODB_URI` لقاعدة اختبار. ينشئ قاعدة مؤقتة باسم `engineering_test_...` ويحذفها عند الانتهاء؛ لا تستخدم حساب الإنتاج للاختبارات.

PowerShell:

```powershell
$env:TEST_MONGODB_URI="mongodb://127.0.0.1:27017"
npm test
```

اختبار التكامل يغطي إنشاء المدير والمشاريع والموظفين، عزل الكشوفات، رفع الصور، البقاء بعد الخروج والدخول، ونقل الموظف والحذف. لم يُنفذ على MongoDB Atlas أو حساب Cloudflare حي ضمن هذا التسليم، لذلك يجب إكمال تجربة النشر بهذه الحسابات قبل اعتماد النظام للعمل الفعلي.

## تحديث Almasri — سبتمبر 2026

- واجهة عربية وتركية وإنجليزية عبر زر الكرة الأرضية. تُحفظ اللغة على الجهاز. النصوص التي يكتبها المستخدم لا تُترجم آليًا.
- شعار ملون أعلى حقول الدخول بالمنتصف، وخلفيتا الدخول ولوحة التحكم كما أرسلهما صاحب المشروع.
- الموظف يعدل اسمه ومهنته وهاتفه من «حسابي»؛ رقم الدخول والمشروع والصلاحية والتفعيل للمدير فقط.
- المدير يضيف الموظف ويحدد رقم دخوله وكلمة مروره. يمكن تعطيله من قائمة تعديل الموظف باختيار «معطّل»، وتظل سجلاته السابقة محفوظة.
- صفحة «التقارير» متاحة للمدير فقط: تقرير يومي بالأعمال والملاحظات والصور، وباسم المدير الذي أنشأه.
- صفحة «العقود» متاحة للمدير فقط: عقد قابل للتعديل مع شعار Almasri الثابت، تواريخ يدوية، طرفين، بنود، وتوقيع وختم واضحين عند الطباعة.
- اختيار المشروع في التقرير والعقد والكشف يدعم إضافة مشروع جديد يدويًا بدل حصر المستخدم في القائمة الحالية.
- التقرير مسودة قابلة للتعديل ثم معتمد. التعديل بعد الاعتماد يحتاج «إعادة إلى مسودة» ويُحفظ التاريخ والمراجع والإصدار السابق. تحديثان لنفس الإصدار لا يطغى أحدهما على الآخر.
- ترفع صور التقرير أثناء المسودة. صور التقرير محفوظة ضمن تاريخ المراجعات؛ لا تُحذف من الواجهة في هذه النسخة.
- طباعة التقرير مع الشعار الأبيض والأسود أعلى اليمين، والمشروع والتاريخ والاسم ومساحة التوقيع. زر «طباعة / PDF» يفتح نافذة الطباعة: اختر Save as PDF / PDF olarak kaydet. لا يوجد توليد PDF مستقل على الخادم.
- أرشيف تقارير يُبحث فيه برقم التقرير والمشروع والتاريخ.
- سجل نشاط للمدير: منفذ العملية وتاريخها والسجل المتأثر. يبدأ بتسجيل العمليات من تثبيت التحديث؛ لا يسترجع عمليات قديمة لم تكن مسجلة.
- حالات الملاحظة من تعديل الملاحظة: مفتوحة، قيد المعالجة، مغلقة، وموعد المعالجة. عند رفع صورة للكشف يمكنك ربطها بالملاحظة وتصنيفها قبل/بعد المعالجة.
- START-HERE.html يتضمن معاينة دخول ومدير وموظف ونموذج تقرير وعقد. التجربة المحلية تحفظ على نفس المتصفح؛ العمل المشترك والحفظ المركزي يحتاجان MongoDB والخادم.
- بطاقة تسجيل الدخول متمركزة داخل اللوحة الزجاجية المدمجة، مع حقول وأزرار شفافة وإضاءة داخلية متجاوبة مع الكمبيوتر والموبايل.

## إنشاء حساب المدير في MongoDB (اختياري)

الطريقة الأسهل هي فتح الموقع بعد ضبط `MONGODB_URI` و`SETUP_TOKEN` ثم اختيار «تهيئة النظام لأول مرة». إذا أردت استخدام أداة التهيئة من PowerShell، أدخل كلمة المرور في متغير مؤقت محليًا ثم شغّل:

```powershell
$env:MONGODB_URI="ضع رابط MongoDB هنا"
$env:OWNER_PASSWORD="ضع كلمة مرور قوية هنا"
$env:OWNER_EMPLOYEE_NO="05340173180"
npm run init-owner
```

لا تُحفظ كلمة المرور أو رابط MongoDB في GitHub، ولا تُرفع أدوات التهيئة أو نسخة التجربة المحلية ضمن مجلد `public`.

اختبار التحديث الأخير: تحقق آلي من الدخول الصحيح ورفض كلمة مرور خاطئة، فتح نموذج تقرير جديد من الزر، حفظ ملاحظته، بقائه بعد إعادة التحميل، وتغيير كلمة المرور ورفض القديمة بعد ذلك.
